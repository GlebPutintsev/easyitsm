# Контракт модулей почты (mail) и уведомлений (notifications)

Java: `ru.easyitsm.mail.api`, `ru.easyitsm.mail.events`, `ru.easyitsm.notifications.api`.
REST: `/api/v1/mail-settings/**` (ADM), `/api/v1/notifications/**` (любой вошедший),
`/api/v1/notification-settings/templates/**` (ADM).

## Для других модулей

```
UUID MailOutbox.enqueue(OutgoingMail)      // письмо в очередь; уйдёт после коммита транзакции
void Notifier.notify(userId, kind, title, body, link, email) // центр уведомлений + push (+ письмо)
```

События: `InboundMailProcessed` (итог разбора входящего письма), `MailDeliveryFailed` (письмо не доставлено
после всех повторов). Уведомления о заявках, SLA, согласованиях и сбросе пароля модуль notifications строит
сам по событиям этих модулей, вызывать его не нужно.

## Входящая почта (CHN-01, CHN-02, поток 6.4)

1. Ящик: IMAP (непрочитанные), Microsoft Graph (client credentials) или входящий SMTP (порт
   `easyitsm.mail.inbound-smtp.port`, по умолчанию 2525). Опрос раз в минуту на worker.
2. Защита от петель: `Auto-Submitted`, `X-Auto-Response-Suppress`, `Precedence`, `X-EasyITSM-Loop`, письма
   с собственных адресов; не больше `max-per-sender-per-hour` писем от отправителя (по умолчанию 30).
3. Проверка отправителя: SPF, DKIM, DMARC (или доверенный `Authentication-Results`). Политика ящика:
   `enforce` — отклонить при `p=reject`, карантин при `p=quarantine`; `strict` — карантин при любом провале
   DMARC; `monitor` — только записать. Из карантина письмо принимается вручную.
4. Привязка к заявке: токен ответа в `In-Reply-To`/`References` (`<eitsm.{ticket}.{token}.{delivery}@домен>`)
   или в теме/теле `[ref:INC-000123:token]`. Токен — HMAC от арендатора и заявки, без него номер в теме
   не привязывает письмо. Заявитель и «для кого» пишут публичный ответ, исполнитель и наблюдатели —
   внутреннюю заметку, посторонний — новую заявку. Ответ в закрытую заявку создаёт новую.
5. Новая заявка: тип и группа из настроек ящика, отправитель — пользователь по email (неизвестный отправитель
   записывается в журнал, заявка не создаётся). Цитата предыдущего письма отрезается по строке
   «Ответьте выше этой строки».

Журнал `GET /mail-settings/inbound?verdict=` хранит итог каждого письма; исходное письмо остаётся только
у карантина (для «Принять»).

## Исходящая почта

Очередь `mail_outgoing`, повторы через 1, 5, 30 минут, 2 и 6 часов. Тема несёт номер заявки, тело — строку
ответа и `[ref:…]`. Заголовки `Auto-Submitted: auto-generated`, `X-Auto-Response-Suppress: All`. Письма на
собственные адреса ящиков не отправляются (`suppressed`). После отправки текст письма из очереди удаляется.

## Уведомления (NTF-01, NTF-02, NTF-05)

Шаблон на событие и язык: тема (заголовок в центре и push) и текст письма. Синтаксис: `{{имя}}`,
`{{#имя}}…{{/имя}}`, `{{^имя}}…{{/имя}}`. Для конфиденциальной заявки название, описание, ответы и причины
заменяются до шаблона, поэтому шаблон не может их раскрыть (NTF-05). Push — Web Push RFC 8291 с ключом
VAPID арендатора; подписки принимаются только для известных push-сервисов браузеров.
