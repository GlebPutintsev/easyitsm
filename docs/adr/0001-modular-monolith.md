# ADR-0001. Модульный монолит на Spring Modulith

Статус: принято, 2026-11-05.

## Контекст

Коробочный продукт до 5 000 пользователей ставится в том числе в закрытый контур заказчика без интернета (ТЗ, разделы 1.3 и 6). Каждый дополнительный сервис — ещё один образ, версия и точка отказа на каждой площадке.

## Решение

Один артефакт `core` (Java, Spring Boot, Spring Modulith). Модули — пакеты `ru.easyitsm.<module>` с подпакетами `api`, `events` и `internal`. Тест `ModularityTests` проверяет, что модули обращаются друг к другу только через `api` и `events`. Межмодульные события идут через outbox в PostgreSQL (таблица `event_publication`).

Отдельными процессами остаются только ИИ-шлюз (сетевая изоляция, ADR-09 ТЗ) и агент обнаружения (ставится на серверы заказчика).

## Следствия

- Транзакции внутри одной БД, без распределённых компенсаций.
- Модуль можно выделить в сервис позже, заменив вызовы `api` на HTTP и события на брокер.
- Нарушение границ ломает сборку, а не обнаруживается на ревью.
