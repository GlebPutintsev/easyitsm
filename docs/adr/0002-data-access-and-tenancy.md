# ADR-0002. Доступ к данным и изоляция арендаторов

Статус: принято, 2026-11-05.

## Решение

- Spring Data JDBC и `JdbcClient` вместо JPA: предсказуемый SQL, прямая работа с JSONB и RLS, нет ленивой загрузки.
- Каждая таблица с данными заказчика содержит `tenant_id` и политику RLS `tenant_id = app_current_tenant()`.
- Приложение подключается ролью `easyitsm_app` без `BYPASSRLS` и без права менять схему. Миграции выполняет роль-владелец `easyitsm_owner`.
- `TenantAwareDataSource` при каждой выдаче соединения выполняет `set_config('app.tenant_id', …)`. Без арендатора значение пустое, и RLS не возвращает ни одной строки.
- Фоновые задачи явно задают арендатора через `TenantContext.runAs`. Задачи по всем арендаторам вызывают функции `SECURITY DEFINER`, принадлежащие владельцу.
- Ключи UUIDv7 генерирует приложение (`Ids.newId()`).
- Версии миграций — метка времени `VYYYY_MM_DD_HHMM__<модуль>_<описание>.sql`, Flyway работает с `out-of-order`, чтобы ветки разных модулей сливались в любом порядке.

## Последствия

Чужая запись для API выглядит как отсутствующая: 404, а не 403 (приёмочный сценарий AT-01). Тест `TenantIsolationTest` проверяет RLS напрямую SQL-запросами без фильтра по арендатору.
