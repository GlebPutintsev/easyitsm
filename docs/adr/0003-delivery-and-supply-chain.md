# ADR-0003. Поставка, цепочка поставки и лицензия

Статус: принято, 2026-11-05.

## Решение

**Образы.** Ядро — `gcr.io/distroless/java21-debian12:nonroot`, веб-клиент — собранный SPA и статический сервер на Go в `distroless/static:nonroot`. В образах нет оболочки и пакетного менеджера, пользователь 65532, корневая файловая система только для чтения, временные файлы в `emptyDir` (SEC-34). Один образ ядра работает в ролях `api` и `worker` (`EASYITSM_WORKER_ENABLED`).

**Helm.** Один чарт `deploy/helm/easyitsm` для пилота (по умолчанию: ядро и обработчик в одном поде, встроенный PostgreSQL) и для HA (`values-ha.yaml`). Поды проходят профиль Pod Security `restricted`. NetworkPolicy запрещает весь трафик пространства имён и разрешает только нужные потоки: Ingress → web и api, ядро → PostgreSQL и явно перечисленные внешние системы, мониторинг → порт управления 8081, все → DNS (SEC-35).

**Секреты** монтируются файлами и читаются Spring через `configtree`, а не переменными окружения (SEC-36). Пароли внешней БД чарт не принимает в values: только `existingSecret`.

**Порт управления.** Health и метрики Prometheus — на отдельном порту 8081, который не публикуется через Ingress. Метрики открыты только на этом порту.

**Цепочка поставки (SEC-38, SEC-39).**
- В каждом PR: Semgrep (SAST), Trivy (уязвимости и запрещённые лицензии зависимостей, конфигурация Dockerfile и Helm), gitleaks по всей истории, сборка образов с проверкой Trivy, SBOM CycloneDX, проверка отсутствия оболочки.
- При выпуске (тег `vX.Y.Z`): образы публикуются в GHCR, подписываются cosign ключом вендора, SBOM прикладывается аттестацией. Чарт собирается с digest образов, подписывается и публикуется в OCI-реестр. Офлайн-комплект содержит образы с подписями, чарт, SBOM, helm и cosign, подписанный список контрольных сумм и установщик.
- Подпись ключом, а не keyless, и без журнала прозрачности Rekor: заказчик в закрытом контуре проверяет подписи без интернета, а сведения о выпусках не уходят в публичный журнал.
- Сторонний образ PostgreSQL для пилота зеркалируется в реестр вендора, проверяется и подписывается так же, как свои.

**Лицензия (ADM-07).** Файл `easyitsm-license/1`: JSON с полезной нагрузкой в base64 и подписью Ed25519 над её байтами. Открытые ключи вендора вшиты в приложение (`resources/licensing/keys/<kid>.pub`), источник только classpath. Файл выпускается скриптом на OpenSSL без серверов вендора. Без лицензии или после окончания срока продукт работает с лимитом 3 агента, заявки не блокируются.

## Отвергнуто

- Образы на Alpine или Debian slim: в них есть оболочка и пакетный менеджер.
- Keyless-подпись Sigstore: требует Fulcio и Rekor при проверке или сложной офлайн-настройки доверенного корня.
- Подпись чарта через `helm package --sign` (GPG): отдельный ключ и инструмент, cosign уже нужен для образов.
- Проверка лицензии на сервере вендора: противоречит работе в закрытом контуре.

## Что осталось на 1.0 (SEC-37)

Закрепление базовых образов и GitHub Actions по digest, изолированная сборка с provenance SLSA Level 3, отдельная задача миграций перед выкаткой (сейчас Flyway выполняется при старте пода под блокировкой), ShedLock для нескольких реплик worker.
