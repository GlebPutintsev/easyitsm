# Агент обнаружения Easy ITSM

Агент собирает сведения о серверах и узлах сети и загружает их в CMDB (CFG-04). Это один исполняемый файл
без зависимостей: Linux amd64 и arm64, Windows amd64. Данные уходят пакетами через API загрузки источников,
дальше CMDB сама опознаёт КЕ, применяет приоритет источников и поднимает конфликты на экране «Сверка» (CFG-05).

## Что собирает

**Сервер, на котором работает агент** (`host`, включено по умолчанию):

| Что | Класс КЕ | Атрибуты |
| --- | --- | --- |
| Виртуальная машина (гипервизор опознан по DMI или флагу `hypervisor` процессора) | `virtual_machine` | `hostname`, `domain`, `fqdn`, `ip_address`, `os`, `os_version`, `cpu_count`, `ram_gb`, `vm_uuid`, `hypervisor` |
| Физический сервер (есть сведения DMI) | `physical_server` | те же, кроме ВМ-атрибутов, плюс `serial_number`, `vendor`, `model` |
| Платформа не определена (контейнер, Windows, macOS) | `server` | имя, адрес, ОС, процессоры |
| СУБД на стандартном порту (PostgreSQL 5432, MySQL 3306, Oracle 1521, MS SQL 1433, MongoDB 27017, Redis 6379, ClickHouse 8123, Cassandra 9042, Db2 50000) | `database` со связью «Работает на» сервер | `engine`, `port` |

Ключ сервера в источнике — `host:<machine-id>`: он не меняется при смене имени и адреса. Без machine-id —
`host:<fqdn>`. Сведения о платформе на Linux читаются из `/etc/os-release`, `/proc` и `/sys/class/dmi/id`;
серийный номер и UUID платформы доступны только root. На Windows пока собираются имя, ОС и число процессоров.

**Узлы сети** (`scan`, выключено по умолчанию): обход IPv4-сетей TCP-подключениями к портам 22, 80, 135,
443, 445, 3389, 5985, 8080, 8443. Узел живой, если порт принял соединение или отказал. Имя узла берётся из
обратной зоны DNS. Ключ узла — `ip:<адрес>`, класс задаётся для каждой сети: `server`, `network_device` или
`workstation`. Обход не проверяет уязвимости и не входит на узлы.

Агент шлёт только атрибуты стандартных классов CMDB. Пароли, токены и ключи агент не собирает, а CMDB их и
не примет (CFG-08).

## Установка

1. В Easy ITSM: **CMDB → Источники → Добавить источник**, вид «Обнаружение», приоритет 20 (ручной ввод — 10,
   поэтому агент не перезапишет то, что люди поправили руками). Откройте источник и нажмите
   **Выпустить токен**. Токен показывается один раз.
2. На сервере (Linux):

   ```sh
   tar -xzf easyitsm-discovery-agent-<версия>-linux-amd64.tar.gz && cd easyitsm-discovery-agent-*
   install -m 755 discovery-agent /usr/local/bin/
   install -d -m 750 /etc/easyitsm
   install -m 640 discovery.example.json /etc/easyitsm/discovery.json   # укажите server
   install -m 600 /dev/null /etc/easyitsm/discovery.token               # вставьте токен
   discovery-agent check
   install -m 644 easyitsm-discovery.service /etc/systemd/system/
   systemctl enable --now easyitsm-discovery
   ```

   Вместо службы можно запускать `discovery-agent once` по cron или таймеру systemd.
3. Проверьте подпись архива перед установкой в закрытом контуре:
   `cosign verify-blob --key cosign.pub --signature <архив>.sig <архив>`.

## Команды

| Команда | Что делает | Код выхода |
| --- | --- | --- |
| `run` | обходы по расписанию `interval` (±10 %, чтобы сотни агентов не приходили одновременно) | 0 при остановке |
| `once` | один обход | 0 — принят, 1 — пакет не принят, 2 — ошибка настроек |
| `check` | проверить адрес, сертификат и токен; показать источник | 0 — источник принимает данные |
| `print` | собрать и вывести объекты в JSON, ничего не отправляя; токен не нужен | 0 |
| `version` | версия | 0 |

Файл настроек по умолчанию `/etc/easyitsm/discovery.json` (Windows — `C:\ProgramData\EasyITSM\discovery.json`),
другой — флагом `-config`.

## Настройки

```json
{
  "server": "https://itsm.example.ru",
  "tokenFile": "/etc/easyitsm/discovery.token",
  "caFile": "/etc/easyitsm/ca.pem",
  "environment": "production",
  "interval": "6h",
  "agentId": "dc1-scanner",
  "logFormat": "text",
  "logLevel": "info",
  "host": {
    "enabled": true,
    "domain": "corp.local",
    "databases": true,
    "databasePorts": { "5433": "PostgreSQL", "6379": "" }
  },
  "scan": {
    "enabled": true,
    "fullSweep": true,
    "networks": [{ "cidr": "10.0.10.0/24", "classCode": "server", "environment": "production" }],
    "exclude": ["10.0.10.1", "10.0.10.128/25"],
    "ports": [22, 443, 3389],
    "timeout": "500ms",
    "concurrency": 64,
    "maxHosts": 4096,
    "reverseDns": true
  }
}
```

- `server` и токен можно задать переменными `EASYITSM_URL` и `EASYITSM_DISCOVERY_TOKEN`. В файле настроек
  токена нет намеренно: файл токена — с правами 600, агент предупредит, если его читают другие.
- Токен передаётся только по https. `caFile` — сертификат внутреннего УЦ, если им выпущен сертификат системы.
  `allowHttp: true` — только для стенда разработчика (для `localhost` не нужен).
- `host.domain` — домен, если сервер не знает своего FQDN. `databasePorts` добавляет порты СУБД, пустая
  строка отключает стандартный.
- `scan.maxHosts` защищает от опечатки в маске: сеть больше лимита — ошибка настроек, а не обход /8.
- Неизвестный ключ в файле — ошибка: опечатка не пройдёт молча.

## Как агент загружает данные

- Обход получает номер `<agentId>-<время UTC>`, пакеты — `<обход>-0001`, `-0002`… До 1000 объектов и 4 МБ в
  пакете (сервер принимает до 5 МБ). Если сервер ответит 413, агент делит пакет пополам.
- Сбой сети, 429 и 5xx агент повторяет до 6 раз с паузой 2, 4, 8… секунд (учитывает `Retry-After`) и тем же
  номером пакета: CMDB применит пакет один раз и на повтор вернёт сохранённый результат.
- Ошибки 400, 401, 403, 409 не повторяются: обход завершается с кодом 1, причина — в журнале.
  `source_inactive` — источник выключен в CMDB, `invalid_token` — токен отозван или перевыпущен.
- Объект с ошибкой (например, атрибут не прошёл проверку) не мешает остальным; агент пишет его ключ, код и поле.
- `scan.fullSweep: true`: после всех пакетов агент шлёт завершающий пакет (`final`). Объекты источника, которых
  не было в обходе, CMDB отметит неактуальными («не виден с …»). Если хоть один пакет не принят, завершающий
  пакет не отправляется. КЕ из эксплуатации сама не выводится: это решение человека.

### Сколько источников заводить

- **Агенты на серверах** — один источник на всех (например, `servers`), `fullSweep` не включать: каждый агент
  видит только свой сервер, и завершающий пакет одного агента отметил бы неактуальными все остальные.
  Актуальность таких КЕ CMDB считает по сроку источника (по умолчанию 30 дней без пакета).
- **Обход сети** — отдельный источник на каждый сканер (например, `scan-dc1`) с `fullSweep: true` и приоритетом
  ниже агентов на серверах (например, 30): сведения с сервера точнее, а расхождения по адресу попадут в «Сверку».

## Разработка

```sh
go test -race ./...
go run . -config deploy/discovery.example.json print
./build.sh 1.0.0 dist        # архивы для выпуска
```

Протокол — `POST /api/v1/cmdb/ingest/batches` и `GET /api/v1/cmdb/ingest/source` с заголовком
`Authorization: Bearer eitsm_cmdb_…`, контракт — `docs/api/cmdb-contract.md`, раздел «Загрузка из источников».
