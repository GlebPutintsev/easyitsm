# Easy ITSM — план разработки

Основа: `ТЗ.md` от 5 ноября 2026. План переводит ТЗ в архитектуру репозитория, порядок работ и набор задач, которые можно вести параллельно.

## 1. Что строим

Коробочная ITSM-платформа до 5 000 пользователей: один код для контура заказчика (в том числе без интернета) и облака. Отличия от рынка: работает сразу после мастера настройки, безопасность и профиль закрытого контура в ядре, ИИ на локальной модели, одна редакция без платных модулей.

Этапы (раздел 13 ТЗ):

| Этап | Содержимое | Развёртывание |
| --- | --- | --- |
| **MVP** | Ядро заявок, инциденты, запросы и каталог, знания, SLA, портал, почта, базовая автоматизация, уведомления, готовые дашборды, мастер настройки, аудит, вход и MFA | Контур заказчика, профиль RU |
| **1.0** | Изменения и CAB, проблемы, крупные инциденты, CMDB, активы, ИИ-шлюз, мессенджеры, конструктор отчётов и форм, JIT-доступ | + облако RU |
| **2.0** | Релизы, миграция из других ITSM, агенты ИИ, телефония, BI-витрина, MCP | + облако INT |

## 2. Архитектура

Модульный монолит (ADR-01…ADR-10 ТЗ без изменений):

```
            React SPA (портал · рабочее место · управление)
                          │ REST /api/v1 + WebSocket
 ┌────────────────────────┴───────────────────────────┐
 │  core  (Java, Spring Boot, Spring Modulith)         │
 │  identity · tickets · sla · catalog · knowledge ·   │
 │  notifications · automation · reporting · audit ·   │
 │  integrations · changes · problems · cmdb · assets  │
 │  platform-kernel: tenant, RLS, outbox, ошибки, ...  │
 └──────┬─────────────┬──────────────┬────────────────┘
        │             │              │ HTTP, отдельный сегмент
   PostgreSQL     S3, Valkey,     ai-gateway (Python, FastAPI)
   (RLS, outbox)  OpenSearch      discovery-agent (Go) → CMDB API
```

Один и тот же образ core запускается в двух ролях: `api` (HTTP) и `worker` (outbox, SLA-таймеры, почта, рассылки). Роль задаётся профилем Spring.

Правила, обязательные для всех модулей:

1. Модуль — Java-пакет `ru.easyitsm.<module>`. Наружу видны только `api` (интерфейсы, DTO) и `events` (доменные события). Всё остальное — `internal`. Границы проверяет тест Spring Modulith в CI.
2. Модуль владеет своими таблицами. Чужие таблицы не читаются, только через API модуля или события.
3. Каждая таблица с данными заказчика содержит `tenant_id`, RLS включена. Приложение ходит в БД под ролью без `BYPASSRLS`, арендатор ставится в транзакции через `set_config('app.tenant_id', …)`.
4. Ключи UUIDv7, служебные поля `created_at/by`, `updated_at/by`, `version`. Время в `timestamptz` UTC.
5. Миграции Flyway в `db/migration/<module>/`, номера с префиксом модуля, только обратно совместимые.
6. Межмодульные события идут через transactional outbox (Spring Modulith event publication registry в PostgreSQL).
7. API: `/api/v1`, ошибки RFC 9457 с `trace_id`, курсорная пагинация, `Idempotency-Key`, `ETag/If-Match`. OpenAPI 3.1 генерируется из кода и лежит в `docs/api/openapi.yaml`, фронтенд генерирует клиент из него.
8. Права проверяются на сервере на каждом запросе (`@PreAuthorize` + проверка объекта ABAC). Каждое правило доступа покрыто тестом.

## 3. Стек и версии

| Слой | Выбор |
| --- | --- |
| Бэкенд | Java 21 LTS (переход на 25 LTS отдельной задачей), Spring Boot 4.1, Spring Modulith 2.1, Spring Security, Spring Data JDBC и JdbcClient (без JPA, ADR-0002), Flyway, Maven |
| БД | PostgreSQL 16+ (Postgres Pro для профиля RU) |
| Фронтенд | React 19, TypeScript, Vite, Mantine 9 (компоненты, темы, доступность), TanStack Query, React Router, i18next, клиент из OpenAPI |
| ИИ-шлюз | Python 3.12+, FastAPI (с 1.0) |
| Агент обнаружения | Go (с 1.0) |
| Инфраструктура | Valkey, OpenSearch, S3 (moto для разработки), Keycloak, OpenBao |
| Поставка | Docker-образы без оболочки, Helm, CycloneDX SBOM, cosign |
| Наблюдаемость | OpenTelemetry, Prometheus, Grafana, Loki, Tempo |

Почему не менять стек ТЗ: Java и Spring дают LDAP, SAML, Kerberos и модульные границы из коробки, а это самая дорогая часть для коробочного продукта.

## 5. Порядок работы

1. **Фундамент** (этот тред): каркас репозитория, platform-kernel, шаблон модуля, фронтенд-оболочка, dev-окружение, CI. Без него параллельные треды разойдутся в соглашениях.
2. **Волна 1** — параллельно, после фундамента.
3. **Волна 2** — после того как ядро заявок отдаст API и события.
4. **Волна 3** — модули 1.0.

Каждый тред работает в своей ветке и своём пакете, меняет общие файлы (kernel, корневые конфиги) только небольшими отдельными PR и сообщает о них в тред фундамента.

## 8. Открытые вопросы к владельцу продукта

Не блокируют старт, но влияют на 1.0 (раздел 13.4 ТЗ):

1. Первый поток заказчиков: коммерческие компании, госсектор или КИИ.
2. Модель лицензирования: по агентам, по сотрудникам или по инсталляции. Пока закладываем подписанный файл лицензии с лимитом агентов.
3. ИИ-модель по умолчанию и кто платит за GPU.
4. Vault или OpenBao. Пока OpenBao из-за лицензии.

## 9. Принятые допущения

- Java 21 вместо 25 на старте, потому что 21 есть во всех сборочных образах; переход тривиален.
- Сборка Maven, один артефакт `core`, без деления на Maven-модули: границы держит Spring Modulith.
- Пакет `ru.easyitsm`, рабочее название продукта Easy ITSM.
